# Question Review Criteria

**Version:** 1.1
**Last Updated:** 2025-01-11  
**Purpose:** Standard framework for evaluating diagnostic questions before release

---

## Criteria

| # | Criterion | What We're Checking | Pass If... |
|---|-----------|---------------------|------------|
| 1 | **Binary Clarity** | Yes/No without ambiguity | A CFO can answer definitively without "it depends" |
| 2 | **Maturity Fit** | L1→L4 progression makes sense | L1 = basics exist, L2 = structured, L3 = optimized, L4 = advanced/predictive |
| 3 | **Diagnostic Value** | Answer reveals meaningful insight | "No" exposes a real gap; "Yes" confirms real capability |
| 4 | **Why It Matters** | Help text explains business impact | Reader understands *so what* if they answer No |
| 5 | **Plain Language** | No jargon | Non-finance executive could understand the question |
| 6 | **Logical Sequence** | Questions flow sensibly within objective | Earlier questions don't assume later ones are done |
| 7 | **No Redundancy** | No overlap between questions | Each question tests something distinct |
| 8 | **Critical Flag Validity** | If critical, truly gating | A "No" here should block Green status for the practice |
| 9 | **Impact/Complexity Calibration** | Scores feel right | High impact (4-5) = material business difference; Low complexity (1-2) = quick win |
| 10 | **Level-Appropriate Scope** | Realistic for maturity level | L1 achievable by any company; L4 genuinely advanced for mid-market |
| 11 | **FP&A Centricity** | Tests FP&A capability, not just outcome | Question names FP&A as the actor or clearly tests an FP&A behavior |

---

## Maturity Level Definitions

| Level | Label | Expectation |
|-------|-------|-------------|
| L1 | **Foundational** | Basic capability exists; any company should have this |
| L2 | **Structured** | Formalized processes with clear ownership |
| L3 | **Optimized** | Proactive, integrated, driver-based approaches |
| L4 | **Advanced** | Predictive, automated, or AI-enhanced capabilities |

---

## Impact & Complexity Scoring Guide

### Impact (1-5)
- **5** — Strategic; materially affects P&L, cash, or decision quality
- **4** — Significant operational improvement
- **3** — Meaningful efficiency or visibility gain
- **2** — Incremental improvement
- **1** — Nice to have

### Complexity (1-5)
- **1** — Quick win; achievable in days with no dependencies
- **2** — Low effort; weeks, minimal coordination
- **3** — Moderate; requires cross-functional effort
- **4** — Significant; months, system changes likely
- **5** — Major transformation; requires technology investment or cultural change

---

## Review Process

1. Review questions grouped by **Objective**
2. For each question, assess against all 11 criteria
3. Flag issues with specific criterion number (e.g., "Fails #1 - ambiguous")
4. Propose revision or recommend removal
5. Re-review flagged questions after revision

---

## Usage

Apply this framework when:
- Adding new questions to the diagnostic
- Reviewing existing questions for MVP or version release
- Responding to user feedback about question clarity
- Calibrating scoring weights across objectives
